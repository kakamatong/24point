# 24点对战 · 好友排行榜（微信开放数据域）技术方案

| 项 | 内容 |
|---|---|
| 文档版本 | v1 （2026-10-14） |
| 适用工程 | workspace/main/24point（游戏 ID 10003，微信小游戏） |
| 相关代码 | assets/scripts/view/rank/ 、assets/scripts/modules/Rank.ts 、assets/scripts/frameworks/utils/sdk/MiniGameUtils.ts |
| 目标需求 | 在游戏内提供「好友排行榜」（基于微信关系链数据） |

---

## 1. 背景与目标

现状：游戏已有「每日排行榜」，走服务端接口（大厅 gameRank/getRankList，见 assets/scripts/modules/Rank.ts），展示的是全服/分段数据，与微信好友无关。

目标：新增「好友排行榜」——展示**当前用户也玩过本游戏的好友**的分数排名（头像 + 昵称 + 分数），数据来自微信关系链，由开放数据域（子域）实现。

**与现有服务端榜的关系：并列共存**（新增一个页签），不改动、不复用现有服务端榜单逻辑。

---

## 2. 微信侧关键约束（必须遵守）

| API | 作用 | 可调用位置 | 基础库 |
|---|---|---|---|
| wx.setUserCloudStorage | 上报自己的托管数据（榜单数据源） | 主域 + 子域 | 1.9.92 |
| wx.removeUserCloudStorage | 删除指定 key 的托管数据 | 主域 + 子域 | 1.9.92 |
| wx.getUserCloudStorage | 读取自己的托管数据 | 仅子域 | 1.9.92 |
| wx.getFriendCloudStorage | 读取「同玩好友」的托管数据 | 仅子域 | 1.9.92 |
| wx.getGroupCloudStorage | 读取「同群成员」数据（需 shareTicket） | 仅子域 | 1.9.92 |
| wx.getPotentialFriendList | 对游戏感兴趣但未玩的好友 | 仅子域 | 2.9.0 |

**三条硬约束**

1. 关系链数据只在子域可见；子域**无法把数据回传主域**，只能把结果**画到 sharedCanvas**，主域再贴图显示。
2. 好友榜只能显示好友**当前的托管值**，没有历史/时间窗口 —— 因此**日榜/周榜不能建立在开放域上**。
3. 只有**托管过数据**的用户才被视为「玩过」，才会出现在 getFriendCloudStorage 结果里（即：只上报、不拉取的玩家不会出现在榜上）。

## 3. 总体设计

~~~text
┌─────────────────── 主域（Cocos Creator + FairyGUI）───────────────────┐
│  结算/破纪录  →  OpenData.setScore(score)  →  wx.setUserCloudStorage    │
│  好友榜页面    →  把子域 sharedCanvas 贴到指定节点（限定区域）           │
│  触摸事件      →  postMessage({type: touch, x, y})  转发给子域            │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ wx.getOpenDataContext().postMessage
                                ▼
┌─────────────────── 开放数据域（子域，独立工程）────────────────────────┐
│  wx.onMessage：拉取 / 刷新 / 触摸 / 主题                                │
│  wx.getFriendCloudStorage({keyList: [score]})                          │
│  → 排序（降序）→ 绘制头像/昵称/分数/自己高亮 → sharedCanvas             │
└───────────────────────────────────────────────────────────────────────┘
~~~

## 4. 详细设计

### 4.1 托管数据 key 设计

限制：每 openid 每游戏最多 128 个 key-value；单项 key+value 不超过 1KB；单个 key 不超过 128 字节。

| key | value | 说明 |
|---|---|---|
| score | 数字字符串，如 1250 | 好友榜主口径：**累计总分** |
| win | 数字字符串，如 37 | 可选第二页签：胜场数 |
| ts | 秒级时间戳字符串 | 最后更新时间，用于展示与防旧值覆盖 |

说明：key 数量控制在 3 个以内，避免占用 128 额度；不采用日榜 key。

### 4.2 上报策略（主域）

- 触发点：**对局结算后**（结算回调里拿到最新累计分）
- 策略：与本地缓存比较，**只在数值变大时才写**（避免频繁写、避免把大值覆盖成小值）
- 缓存：用 wx.getStorageSync 保存 lastUploadedScore，冷启动读取
- 容错：setUserCloudStorage 失败不阻塞主流程，静默重试（最多 2 次，下次结算再补）

~~~js
// 主域：OpenData.setScore(score)
const last = Number(wx.getStorageSync('odScore') || 0);
if (score > last) {
  wx.setUserCloudStorage({
    KVDataList: [{ key: 'score', value: String(score) }],
    success: () => wx.setStorageSync('odScore', score)
  });
}
~~~

### 4.3 子域实现要点

- 入口：openDataContext/index.js，注册 wx.onMessage 处理：init / refresh / touch / theme
- 拉取：wx.getFriendCloudStorage({ keyList: ['score'] }) → 数组 [{openId, avatarUrl, nickName, data}]
- 排序：按 data.score 数值降序；把「自己」插入并高亮（自己可从 wx.getUserCloudStorage 或 getFriendCloudStorage 中的自己项拿到）
- 绘制：头像用 wx.createImage 加载 avatarUrl（需缓存，避免闪烁）；文字用 canvas fillText；分数格式化（万位可缩写）
- 滚动：子域自己维护 offset，由主域转发的触摸事件驱动惯性滚动
- 空态/未授权/网络失败：画出对应占位文案（子域没有主域 UI 组件可用）

### 4.4 主域贴图与事件转发

- 取子域画布：const ctx = wx.getOpenDataContext(); 画布为其 canvas（sharedCanvas）
- 贴图：Cocos Creator 3.8 中把 sharedCanvas 作为纹理源，渲染到排行榜页预留节点；尺寸按 UI 区域像素设置（注意设备像素比 DPR）
- 事件：主域监听该区域的 touchstart/touchmove/touchend，把坐标（转成子域画布坐标系）postMessage 给子域
- 刷新：页面打开时 postMessage({type:'refresh'})；关闭时停止转发以省性能

### 4.5 授权与降级

- getFriendCloudStorage 需要用户授权（文档标注 scope.WxFriendInteraction）
- 首次进好友榜：未授权 → 显示引导（按钮跳授权/设置页），不阻塞主流程
- 拒绝授权：显示「去授权」占位
- 基础库 < 1.9.92 或非微信环境：**隐藏好友榜页签**，仅保留服务端每日榜

## 6. 兼容性与风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 子域工程独立构建 | Cocos Creator 3.8 需单独构建开放数据域产物，主工程不能直接引用 | 建立独立构建配置与发布流程 |
| 视觉风格割裂 | 子域只能手绘，与 FairyGUI 风格可能不一致 | 统一配色/字号规范，子域按规范绘制 |
| 授权被拒 | 用户拒绝关系链授权 | 占位引导，不阻塞；服务端榜仍可用 |
| 好友数据稀少 | 只有同玩且上报过的好友上榜 | 上报要覆盖所有模式（匹配/私房/单机可选） |
| 老版本基础库 | < 1.9.92 | 隐藏好友榜页签 |
