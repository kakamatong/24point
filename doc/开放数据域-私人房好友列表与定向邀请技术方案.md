# 24点对战 · 私人房「好友列表 + 定向邀请」技术方案

| 项 | 内容 |
|---|---|
| 文档版本 | v1 （2026-10-14） |
| 适用工程 | workspace/main/24point（游戏 ID 10003，微信小游戏） |
| 相关代码 | assets/scripts/view/privateRoom/PrivateRoomView.ts 、assets/scripts/frameworks/utils/sdk/MiniGameUtils.ts |
| 目标需求 | 私人房内弹出好友列表，点击可**定向分享邀请**指定好友入房 |

---

## 1. 背景与目标

现状：私人房已有「创建房间 / 加入房间（输入房间号）」以及一个通用「邀请好友」入口（走 MiniGameUtils.shareAppMessage，拉起分享面板，用户自己选人）。

目标：私人房内新增**好友列表弹窗**，点某个好友即可**定向**把邀请卡片发给该好友（不是拉起面板让用户自己选），卡片携带房间号，对方点开可直接进入本房间。

---

## 2. 微信侧 API 事实（已核对官方文档）

### 2.1 wx.shareMessageToFriend —— 定向分享（核心）

- **基础库 2.9.0** 起支持
- **只能在开放数据域（子域）使用**
- 参数：`openId`（必填，发送对象）、title、imageUrl、imageUrlId、success/fail/complete
- 接收者打开后，可用 `wx.modifyFriendInteractiveStorage` 传 `quiet=true` 发起一次**无需弹框确认**的好友互动

注意事项（官方原文要点）：

1. **定向分享不允许直接在开放数据域设置 query 参数** —— 需要设置请改在**游戏域**调用 `wx.setMessageToFriendQuery`
2. **imageUrl 不能是网络图片**：若是网络图，需先在游戏域 `wx.downloadFile` 下载到本地，再用 `OpenDataContext.postMessage` 把本地路径发给子域使用；不填或错填网络图时使用**游戏画面截图**

### 2.2 wx.setMessageToFriendQuery —— 给定向分享带 query（游戏域）

- 作用：设置 `wx.shareMessageToFriend` 接口 query 字段的值
- 参数：`shareMessageToFriendScene`（0 ~ 50 的场景数字，必填）、`query`（字符串，长度需在 **128** 之内，必填）
- 返回：boolean（是否设置成功）
- **接收方读取方式**（注意与普通启动参数不同）：

~~~js
// 发送方（游戏域，发邀请前设置）
wx.setMessageToFriendQuery({ shareMessageToFriendScene: 1, query: 'roomId=123456' });

// 接收方（点卡片进入后）
const q = wx.getEnterOptionsSync().query;
q.shareMessageToFriendScene;  // 1
q.query;                      // 'roomId=123456'
~~~

- 特殊符号（? 和 & 等）需自行 `encodeURIComponent` / `decodeURIComponent`

### 2.3 wx.modifyFriendInteractiveStorage —— 好友互动（可选增强）

- **基础库 2.7.7** 起支持，**仅子域可用**
- 参数：key（只能 `1` ~ `50`）、opNum（只能 `1`）、operation（只能 `add`）、toUser（目标好友 openId）、quiet、title/imageUrl（2.9.0）
- `quiet=true` 在「从定向分享卡片进入」场景下有效，代表**分享反馈动作**，此时 toUser 默认为分享者 openId
- 依赖：需上传 **JSServer 校验函数 `checkInteractiveData`**（返回 `{ret:true}` 才允许修改）；`game.json` 配 `modifyFriendInteractiveStorageTemplates` 文案
- 常见错误码：`-17006` 非好友关系、`-17007` 非法 toUser openId、`-17011` JSServer 校验失败

### 2.4 好友列表数据源（子域）

| API | 拿到什么 | 基础库 |
|---|---|---|
| wx.getFriendCloudStorage | **同玩好友**（也玩过且托管过数据） | 1.9.92 |
| wx.getPotentialFriendList | 对游戏感兴趣但**未玩**的好友 | 2.9.0 |

两者都需要关系链授权（scope.WxFriendInteraction）。

## 3. 总体设计（时序）

~~~text
发起方（房主/房内玩家）
  1. 私人房页 → 点「邀请好友」→ 主域 postMessage({type:'openFriendList'})
  2. 子域 getFriendCloudStorage / getPotentialFriendList → 绘制好友列表到 sharedCanvas
  3. 用户点某个好友 → 子域 wx.shareMessageToFriend({ openId, title, imageUrl: <本地路径> })
     ↑ 主域需先调用 wx.setMessageToFriendQuery({shareMessageToFriendScene:1, query:'roomId=XXX'})
  4. 微信把邀请卡片直接发给该好友（定向，不经选择面板）

接收方
  5. 点开卡片进入游戏 → wx.getEnterOptionsSync().query 取 {shareMessageToFriendScene, query}
  6. 主域解析 query 得 roomId → 调「加入房间」流程（预填或直接加入）
  7.（可选）进入后子域 modifyFriendInteractiveStorage(quiet=true) 回执「已接受邀请」
~~~

---

## 4. 详细设计

### 4.1 好友列表（子域）

- 打开时机：主域 postMessage({type:'openFriendList', mode:'friend'|'potential'|'all'})
- 数据：先 getFriendCloudStorage({keyList:['score']})，可选合并 getPotentialFriendList
- 展示：头像（createImage + 本地缓存）、昵称、分数/段位；「已玩 / 未玩」用不同底色
- 交互：主域转发触摸坐标；子域做点击命中 → 命中好友项即触发定向邀请
- 反馈：邀请成功/失败在子域画 toast（子域无法调用主域 UI）

### 4.2 定向邀请链路（关键）

~~~js
// ① 主域（发邀请前，设置房间号 query）
wx.setMessageToFriendQuery({
  shareMessageToFriendScene: 1,          // 自定义场景号：1 = 私房邀请
  query: 'roomId=' + roomId
});

// ② 子域（点好友后，定向分享）
wx.shareMessageToFriend({
  openId: friend.openId,
  title: '来 24 点对战房 ' + roomId + ' 一起玩',
  imageUrl: localShareImgPath,           // 必须是本地路径，不能是网络图
  success: () => drawToast('邀请已发送'),
  fail: (e) => drawToast('邀请失败 ' + e.errMsg)
});
~~~

**顺序要求**：先在游戏域 `setMessageToFriendQuery`，再在子域 `shareMessageToFriend`。

**图片处理**：分享图若用网络图，需主域先 `wx.downloadFile` 落到本地，再 `postMessage` 把路径给子域。

### 4.3 接收方落地（游戏域）

~~~js
const q = wx.getEnterOptionsSync().query || {};
if (Number(q.shareMessageToFriendScene) === 1 && q.query) {
  const params = new URLSearchParams(q.query);   // 或自行 decodeURIComponent + split
  const roomId = params.get('roomId');
  if (roomId) { /* 预填房间号并自动加入，或弹确认后加入 */ }
}
~~~

注意：冷启动用 `wx.getLaunchOptionsSync()`，热启动用 `wx.onShow` / `wx.getEnterOptionsSync()`，**两条都要接**。

### 4.4 邀请回执 / 好友互动（可选）

- 接收方从定向卡片进入后，可在子域调用 `wx.modifyFriendInteractiveStorage({ key:'1', opNum:1, operation:'add', quiet:true })` 回执分享者
- 适合做「邀请成功 +1 次」之类的互动计数；**需要 JSServer 函数与 game.json 模板配置**，本期可不做

### 4.5 触摸与滚动

- 子域无触摸事件：主域监听列表区域，把坐标（换算到子域画布坐标系）postMessage 给子域
- 子域负责惯性滚动、点击命中（区分滑动与点击的阈值）

## 6. 兼容性与风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 基础库门槛 | shareMessageToFriend 需 **2.9.0**；低版本不可用 | 版本判断，降级为原来的「拉起分享面板」 |
| 定向分享风控 | 可能存在频率/额度限制（官方文档未给出明确数字） | **小范围实测**，必要时加节流与失败提示 |
| query 长度限制 | `query` 需在 128 字节内 | 只放 roomId（短号），不放长参数 |
| 特殊字符 | query 含特殊符号需 encodeURIComponent | 房间号建议纯数字，免编码问题 |
| 分享图限制 | 不能用网络图 | 用本地打包图，或先 downloadFile 再传路径 |
| 好友列表为空 | 只有同玩好友；未玩好友需 getPotentialFriendList | 空态文案 + 引导去分享拉新 |
| 子域视觉 | 只能手绘，风格可能与 FairyGUI 不一致 | 统一配色/字号规范 |

## 7. 待确认问题（需拍板）

1. 好友列表数据源：**同玩好友**、**感兴趣未玩**、还是**两者合并分两组**？
2. 接收方点卡片后：**直接自动进房**，还是**预填房间号 + 用户点加入**？（建议后者，更可控）
3. 是否要做 **4.4 好友互动回执**（需 JSServer + game.json 模板，工作量增加）？
4. 邀请分享图用哪张？（需本地图片；若沿用现有分享图，确认是代码包内资源）
5. 场景号 shareMessageToFriendScene 约定：1 = 私房邀请；后续是否预留其他场景？
6. 是否保留原「拉起分享面板」入口作为低版本降级与补充？
